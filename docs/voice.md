# Windows 按键语音（2026-11-07）

近期只适配 dsh。更新桌面与 Runtime 后，通过 `/maneki assistant` 或桌宠打开同一助手。dsh 插件仍是入口，语音在桌面 Shell 与共享 Runtime 之间处理；无需把录音、密钥或语音设置交给 dsh。没有全局热键、唤醒词或常驻监听。

## 安装本地组件

ASR 由用户自行准备受信的 [whisper.cpp v1.9.5](https://github.com/ggml-org/whisper.cpp/tree/v1.9.5) Windows 构建及兼容的 GGML 模型，不自动下载或更新。实际验证的是该 tag 的 CPU 构建，`--version` 输出为 `whisper.cpp version: 1.9.5-dev`；程序仅接受 1.9.5 / 1.9.5-dev。其他版本不宣称兼容。该 tag 未提供本轮可用的预编译 release 附件；可按其官方 CMake 说明自行编译，不要把旧版 exe 改名冒充新版。

默认安装位置：

```text
%APPDATA%\com.manekipet.desktop\runtime\speech\whisper\
  whisper-cli.exe
  <该构建所需的相邻 DLL>
  model.bin
```

`model.bin` 是你选定的兼容模型文件。CLI 与模型路径固定，不接受项目配置指定任意程序或参数。缺文件或版本不符时明确报错。组件检测只检查 ASR 文件是否存在；真正调用还会核验 CLI 版本、依赖与模型能否加载。本轮 tiny 模型仅用于管道验证，中文命令存在误识别；请按自己的准确率、延迟与内存需求选模型并人工验收。

TTS 使用 Windows 本机已安装的 System.Speech 语音，通过系统 Windows PowerShell 5 生成内存 WAV。无需配置云端服务。点击“检测语音组件”列出可用的系统语音名称；名称可填入“系统语音名称”，留空使用系统默认。检测不会打开麦克风或播放声音。

## 启用与使用

1. 在助手“设置”中，按需启用“允许按键时使用麦克风”和“启用本地语音识别”，选择语言后保存。两者都开启才允许输入。三项语音开关默认关闭。
2. 按住“按住说话”按钮，或聚焦该按钮后按住空格 / Enter。首次出现系统麦克风授权时由用户处理；权限等待期间松开会取消本轮，迟到的授权不会自行开始录音。授权后需要重新按住。
3. 松开后结束采集、转写并显示识别文本；仍有效的当前轮次自动提交同一对话入口，无需再点发送。每段最长 30 秒，至少 0.3 秒有效音频；静音、空结果、识别失败或取消不提交。点击“取消”、录音时失焦、隐藏/关闭面板或失联会停止本地音频。
4. 可独立开启“启用本地语音回答”。只朗读本客户端主动请求的回复，或点击“朗读最后回复”；每次最多前 150 字。按键说话会先停止朗读，播放失败保留文字，不自动重播。主动提醒不自动播声。

语音复用现有个人对话、待办和提醒规则，不能批准工程操作。可说“待办：买牛奶”或“半小时后提醒我休息”，但 ASR 准确率取决于设备与模型；检查识别文本及实际办事反馈。关闭模型时仍可使用已有规则式文字/语音待办提醒。已经提交的事项不会因取消被假报撤销，需明确修改或删除。提交结果未知时先查历史与待办，不自动换请求 ID 重发。

录音只在内存与进程管道传递，不存入 SQLite 或日志；成功提交的识别文字作为普通主会话消息本地保留。清空聊天会删除消息与摘要，保留去重墓碑及独立待办/提醒。ASR/TTS 均为本地实现；启用的对话模型仍按其独立本地/云端设置处理文字。

## 更新与验证边界

SQLite v4 → v5 前生成 `runtime.db.bak-4`；更早版本按其源版本备份。回退时先停 Runtime，再显式恢复对应备份，不能把新库交给旧 Runtime。桌面与 Runtime 一起更新；旧客户端保存不含 voice 的设置时保留已有语音偏好。

本轮未替换已安装应用。真实麦克风/扬声器、权限弹窗、噪声与口音、识别准确率、休眠/设备切换、安装器与长时资源仍需人工验收。macOS/Linux 未在本机验证，当前内置 ASR/TTS 实现只提供 Windows。自动化、原生构建和资源样本见[验证记录](./audits/2026-11-07-push-to-talk-voice.md)。
