# Maneki Roadmap

> 设计基线 v0.2，2026-10-30 修订。当前仅 M0 完成；后续复选框表示待实现、待验收，完成时补日期与证据路径。
> 本次调整：M1 固定最小动作包；M2 验证 Runtime 与多 harness 接入；新增 M2b 提前验证文字任务闭环；`maneki_remind` 随 M4 提醒服务提供。原有周期估计未覆盖这些验证，撤去旧排期，待 M1/M2 spike 后基于证据重估。

## 依赖与发布原则

```text
M0 → M1 → M2 → M2b ───────────────┐
             ├→ M3（可选语音/模型）├→ M5 → M6
             └→ M4（文字提醒先行）─┘
```

M3 与 M4 可在 M2 稳定的 Runtime/配置/存储接口上独立推进，M2b 不依赖语音。M4 的语音入口依赖 M3，但文字记事与提醒不依赖模型/语音。M5 集成完整体验；禁用可选能力仍可完成文字任务。并行开发须分别控制接口与修改范围，不等于自动采用并行 agent。

- 先发布 Windows 已验证基线；macOS/Linux 是目标平台，分别记录通过、受限或未验证，不以 Windows 验收替代。
- 每阶段只开放已验证能力。harness 接入不满足审批要求时仅观察，不为了通过里程碑而绕过安全策略。
- 所有代码阶段运行 `pnpm -r build && pnpm -r test`；再按下列场景做最小集成/设备验证。只有文档时检查一致性、链接与契约示例，不宣称运行通过。
- 架构与 Interface 调整先同步 [architecture.md](./architecture.md)，设计提交与实现分开。首个可用版本不以第三方技能、市场或多宠为门槛。

## M1 — 最小桌宠与动作包

目标：在 Windows 上运行一只可换装、可交互的小招，验证桌面技术路线。

- [ ] pnpm workspace / TypeScript strict / 最小构建与测试；仅创建 desktop 和实际需要的 core 模块
- [ ] Tauri v2 透明置顶窗、托盘、退出/静音/置顶开关、点击与拖拽
- [ ] Core 的 PetState 与纯动画选择逻辑；Shell 负责播放与窗口交互
- [ ] 动作包 v1 Schema、素材哈希清单、路径/规格/资源校验、缺省 idle；默认包与第二个测试包
- [ ] 带权动画链、动作打断/回退、播放器缓存上限；透明视频与精灵图兼容路径
- [ ] 多显示器、不同 DPI、鼠标穿透与拖拽甩抛边界
- [ ] 三平台透明窗/媒体格式 spike 矩阵，记录素材与系统/WebView 版本；按 architecture §3.3 决定是否需要调整

验收：

- [ ] Windows 安装/启动/托盘退出通过；关窗口与退出行为清楚，未遗留子进程
- [ ] 换包不改业务代码；缺失非 idle 状态可回退；不支持版本、损坏素材与路径穿越拒绝安装，旧包仍可用
- [ ] 点击、拖拽、多屏移动与动画切换可用，记录卡顿与内存；M1 数字不冒充含 Runtime 的最终总占用
- [ ] macOS 真实平台验证并附证据；未验证保持未勾选
- [ ] Linux 真实平台验证并附证据；未验证保持未勾选

## M2 — Runtime、本地接口与状态联动

依赖：M1。目标：harness 干活时宠物能正确表达状态，完成本机运行与接入可行性验证。

- [ ] Node Runtime sidecar 打包与受控 IPC；一个用户配置目录一个 Runtime、SQLite 单一拥有者
- [ ] 启动/连接/关闭/崩溃恢复流程、就绪与降级状态；默认不加载语音或模型
- [ ] HTTP/WS 127.0.0.1 + token/scope + Host/Origin 校验，受信客户端配对、凭证撤销、短期 WS 票据
- [ ] `/v1` OpenAPI/消息 Schema 与输入/并发上限；SQLite 迁移与当前需要的最小任务/审计记录
- [ ] stdio MCP 表达桥：`maneki_say / maneki_set_state / maneki_play / maneki_notify`；stdout 仅协议消息
- [ ] 首个真实 harness 事件 Adapter（Claude Code hooks 优先）；归一来源/会话/任务、去重、乱序保护、快照恢复
- [ ] 最小确定性防打扰规则：静音、通道开关、主动次数限制；此时即约束 MCP 与任务通知
- [ ] 完成/需输入通知、受限会话跳转；来源绑定，不能由普通 MCP 状态意图伪造真实任务完成
- [ ] dsh 与 pi 接入 spike：检查实际版本、事件、会话选择、新建/续接/回答/查询/取消、原生/桥接审批，记录支持与缺口

验收：

- [ ] 安装包无须用户另装 Node；两个 Shell/启动入口不会创建两份 Runtime 或数据库写入者
- [ ] 缺 token、错 scope、不允许的 Host/Origin、票据重放均拒绝；撤销客户端后不可继续操作
- [ ] 真实任务状态联动；正常负载下事件到动画 p95 < 300ms，通知调用 p95 < 1s；记录采样与设备
- [ ] 两个会话事件不串扰；重复终态只通知一次；迟到 progress 不覆盖 completed；断线后快照与增量衔接不漏终态
- [ ] 静音期间 Maneki 不主动弹出/播报；外部 urgency 不能绕过；无语音/模型配置时表达与通知仍可用
- [ ] 统计 Shell/WebView/Runtime/桥/存储的空闲总内存 < 150MB；若未达标记录原因与后续决策，不缩减统计范围
- [ ] Runtime 异常/数据库迁移失败可诊断，未把失联任务标成成功；macOS/Linux 的打包/通知另验并保留证据

## M2b — 提前验证文字任务闭环

依赖：M2 与至少一个通过执行审批验证的 harness。目标：尽早证明“替我派任务并带回结果”可行。

- [ ] 一个明确目标项目/会话的文字派发入口，默认 ask，展示目标与任务内容
- [ ] Core Task Broker：持久化 requestId、状态迁移、同会话串行、有界并发、任务列表
- [ ] 真实 Adapter 提交、查询/对账、补充输入及可用的取消；未支持能力明确禁用
- [ ] 经验证的 harness 原生审批或 bridge 逐步审批；一次批准、摘要绑定、过期拒绝与审计
- [ ] 结果摘要、校验后产物引用、完成通知与会话路由

验收：

- [ ] 在测试项目派发 README 翻译任务，完成后收到通知并能打开真实产物；同一 requestId 不重复执行
- [ ] 实际危险操作在临时测试目录中被执行侧阻塞；拒绝/超时后文件未变，审批参数变更须重新批准
- [ ] Agent 输出里的删除指令仅被展示，不引发 Maneki 新任务；结构化调用缺授权同样拒绝
- [ ] 无审批保障的适配器禁止派发；不启用 skip-permission/全局自动批准选项
- [ ] 提交后断线、回执丢失或 Runtime 重启，先对账；无法查询则显示 unknown，不重发任务
- [ ] 取消未收到确认时不伪报已取消；需要输入时响应绑定原任务/inputId，不能发往另一会话

如果候选宿主均无法满足审批契约，保持此阶段未完成，记录证据和接入限制，先修订方案；M3/M4 的非执行能力可继续建设。

## M3 — 可选对话与可插拔语音

依赖：M2；任务语音入口集成 M2b。目标：文字与语音走同一流程，语音和模型可分别关闭/替换。

- [ ] `ChatProvider / SpeechRecognizer / SpeechSynthesizer` 独立端口，统一超时/取消/错误语义
- [ ] 首个对话 Provider；whisper.cpp 本地 ASR；首个本地 TTS 引擎经许可、资源与打断验证后确定
- [ ] Provider 配置、模型可用性提示、明确启用/关闭；缺模型不自动下载或转云端
- [ ] 按键说话、可见采集状态、气泡与可选 TTS，半双工与点击/按键打断
- [ ] 主动语音邀请 + 用户明确回应；可选短时连续对话有超时与一键停止
- [ ] 可选增强单独验收：VAD、唤醒词、回声抑制/全双工，不作为首个可用版本前置条件

验收：

- [ ] ASR/TTS 分别禁用时功能组合正确；全部语音关闭后不占麦克风/不加载语音模型，文字派发仍可用
- [ ] 替换 ASR、TTS 或对话 Provider 各自不改 Core/harness；用真实实现与故障替身验证取消、超时、迟到响应与释放
- [ ] 无对话模型时，结构化文字任务入口、规则提醒、通知与状态联动仍可用
- [ ] 麦克风拒绝/占用、ASR/TTS 失败回到文字；自身播报不会被当用户命令，语音不批准危险操作
- [ ] 关闭云端立即阻止新云请求并取消在途调用；迟到响应丢弃，失败不换另一云端
- [ ] 基准设备/模型/输入上记录冷启动、ASR p95 < 1.5s 与结束采集到开始回答目标 < 5s；未达标说明瓶颈

## M4 — 记忆、可靠提醒与主动交流

依赖：M2；语音场景额外依赖 M3。目标：文字优先打通“帮我记一下”，不把语音/LLM 设为必需。

- [ ] SQLite memories/reminders/conversations 与版本迁移；用户查看、删除、保留期限
- [ ] 单次提醒时间解析：规则优先，LLM 可选，UTC/原时区保存，歧义先确认
- [ ] 事务写入提醒与待投递项、最近到期唤醒、启动/休眠/时钟变动后补扫
- [ ] 多通道送达与按 reminder/occurrence/channel 去重，区分系统受理/用户确认/失败
- [ ] `maneki_remind` 独立 scope 与用户授权、来源配额；跨来源越权拒绝
- [ ] 主动性引擎扩展触发器/预算；默认静音不穿透，恢复后合并补发，重提显式开启且有上限

验收：

- [ ] 关闭语音与对话模型，通过文字创建/查询/删除提醒；启用语音后复用同一业务流程
- [ ] 创建“半小时后提醒看构建结果”，重启、休眠恢复与时钟变化后按规则补发；两个 Shell 不重复调度
- [ ] 默认静音时段 Maneki 零主动打扰，包括高优先级；恢复后显示原到期时间与待查看事项
- [ ] 注入“发出后记账前崩溃”，记录允许重投边界，Shell 合并重复 ID；不宣称外部通知严格一次
- [ ] OS 拒绝通知显示投递失败，不能标为用户已看见；提醒创建未落库不返回成功
- [ ] 用户数据删除与日志脱敏可核查；云端关闭后不发送记忆/录音；已运行非静音时提醒到通知调用 p95 < 1s

## M5 — 完整任务体验与 overlay 插件

依赖：M2b、M3 基线、M4。目标：把已验证能力组合成桌宠助理，增加经验证的宿主接入。

- [ ] 统一文字/语音意图分流；任务列表、多会话关注、补充输入、审批回到受信 UI
- [ ] dsh overlay 插件连接同一 Runtime；配对、断线、重载与卸载正确释放
- [ ] dsh/pi 等 Adapter 按 M2 spike 的真实能力完善；generic-cli 只提供安全配置范式，不承诺任意 CLI 可派发
- [ ] npm Core 嵌入最小示例，验证不依赖 Shell/Node IO/语音/harness SDK
- [ ] 公开已验收宿主版本、平台、能力矩阵与接入文档

验收：

- [ ] 对小招说“把这个项目 README 翻译成英文”，选择目标、审批、跟踪、交付完整；禁用语音后文字路径同样通过
- [ ] 桌面与 overlay 同时连接时共享任务/提醒；某个 Shell 断开不丢状态、不重复执行；Runtime 失联时显示降级
- [ ] 至少两个不同 harness 的真实接入验证统一契约；分别列出观察与执行能力，缺少的能力不伪装
- [ ] 第三方只嵌入 Core 并注入替身端口即可运行状态/提醒规则示例；无监听端口、模型下载和隐式文件 IO
- [ ] 复测总资源与安全恢复场景；macOS/Linux 各自验收前不宣称正式支持

## M6 — 受控扩展与生态

持续建设；不能用“权限清单”代替安全沙箱。

- [ ] 第三方技能代码隔离方案、broker 权限、资源/目录/网络限制与撤销机制
- [ ] 安装/更新来源验证；若引入签名，明确公钥信任、轮换、撤销与防降级
- [ ] 在 v1 基础上扩展动作包制作/导入工具、素材管线脚本与授权文档，不推迟 M1 的基本格式
- [ ] 社区分发约定、兼容迁移、多宠与文档站，按实际需求逐项推进

开放验收：

- [ ] 恶意技能读未授权目录、联网、执行命令及耗尽资源被实际隔离；普通子进程/Worker/VM 不作为通过证据
- [ ] 更新新增权限需要重新授权；撤销/卸载终止调用并清理凭证，坏包不替换正常版本
- [ ] 若隔离不可行，保留受信内置技能与数据动作包，第三方可执行安装入口保持关闭
