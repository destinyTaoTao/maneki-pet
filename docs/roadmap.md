# Maneki Roadmap

> 设计基线 v0.3，2026-10-30 修订。当前仅 M0 完成；后续复选框表示待实现、待验收，完成时补日期与证据路径。
> 本次调整：首个可用版本定位为可换装桌宠 + dsh 文字任务中间人 + 插件入口；共享 Runtime 无须桌宠窗口。M2b 插件首版不再依赖 M3 语音或 M4 提醒；pi 为第二目标。排期仍待 M1/M2 spike 后基于证据重估。决策与缺口处置见 [审计报告](./audits/2026-10-30-design-audit.md)。

## 依赖与发布原则

```text
M0 → M1 → M2 → M2b（dsh 文字任务与插件首版）→ M5（第二目标/完整体验）→ M6
             ├→ M3（可选语音/模型）───────────┘ 按能力追加
             └→ M4（文字提醒先行）───────────┘ 按能力追加
```

M3 与 M4 可在 M2 稳定的 Runtime/配置/存储接口上独立推进，M2b 不依赖它们。M4 的语音入口依赖 M3，但文字记事与提醒不依赖模型/语音。M5 的第二 harness/库模式只依赖 M2b，整合语音/提醒的验收分别依赖 M3/M4，不把全部集成完成设为发布插件的条件。并行开发须分别控制接口与修改范围，不等于自动采用并行 agent。

- 先发布 Windows 已验证基线；macOS/Linux 是目标平台，分别记录通过、受限或未验证，不以 Windows 验收替代。
- 各阶段以明确列出的 Windows 出口项进入下一阶段；平台矩阵单独跟踪。macOS/Linux 未验证时不阻塞 Windows 开发/发布，也不能勾选这些平台已支持。
- 每阶段只开放已验证能力。harness 接入不满足审批要求时仅观察，不为了通过里程碑而绕过安全策略。
- 所有代码阶段运行 `pnpm -r build && pnpm -r test`；再按下列场景做最小集成/设备验证。只有文档时检查一致性、链接与契约示例，不宣称运行通过。
- 架构与 Interface 调整先同步 [architecture.md](./architecture.md)，设计提交与实现分开。首个可用版本不以第三方技能、市场或多宠为门槛。

## M1 — 最小桌宠与动作包

目标：在 Windows 上运行一只可换装、可交互的小招，验证桌面技术路线。

- [ ] pnpm workspace / TypeScript strict / 最小构建与测试；仅创建 desktop 和实际需要的 core 模块
- [ ] Tauri v2 透明置顶窗、托盘、退出/勿扰/置顶开关、点击与拖拽
- [ ] Core 的 PetState 与纯动画选择逻辑；Shell 负责播放与窗口交互
- [ ] 动作包 v1 Schema、素材哈希清单、路径/规格/资源校验、缺省 idle；默认包与第二个测试包
- [ ] 带权动画链、动作打断/回退、播放器缓存上限；透明视频与精灵图兼容路径
- [ ] 多显示器、不同 DPI、鼠标穿透与拖拽甩抛边界
- [ ] 三平台透明窗/媒体格式 spike 矩阵，记录素材与系统/WebView 版本；按 architecture §3.3 决定是否需要调整

Windows 阶段出口：

- [ ] Windows 安装/启动/托盘退出通过；M1 尚无 Runtime 时退出无遗留进程，M2 后按共享 Runtime 生命周期验收
- [ ] 换包不改业务代码；缺失非 idle 状态可回退；不支持版本、损坏素材与路径穿越拒绝安装，旧包仍可用
- [ ] 点击、拖拽、多屏移动与动画切换可用，记录卡顿与内存；M1 数字不冒充含 Runtime 的最终总占用

跨平台支持矩阵（不阻塞 Windows 下一阶段）：

- [ ] macOS 真实平台验证并附证据；未验证保持未勾选，后续新增 Runtime/音频能力也需补验
- [ ] Linux 真实平台验证并附证据；未验证保持未勾选，后续新增 Runtime/音频能力也需补验

## M2 — Runtime、本地接口与状态联动

依赖：M1。目标：harness 干活时宠物能正确表达状态，完成本机运行与接入可行性验证。

- [ ] 共享 Node Runtime 打包、已安装固定入口启动器与受控 IPC；一个用户配置目录一个 Runtime、SQLite 单一拥有者
- [ ] 启动/连接/关闭/崩溃恢复流程、就绪与降级状态；默认不加载语音或模型
- [ ] HTTP/WS 127.0.0.1 + token/scope + Host/Origin 校验，受信客户端配对、凭证撤销、短期 WS 票据
- [ ] `/v1` OpenAPI/消息 Schema 与输入/并发上限；SQLite 迁移与当前需要的最小任务/审计记录
- [ ] stdio MCP 表达桥：`maneki_say / maneki_set_state / maneki_play / maneki_notify`；stdout 仅协议消息
- [ ] 首个目标 dsh 的真实事件 Adapter；归一来源/会话/任务、去重、乱序保护、快照恢复。Claude hooks 可按需作对照，不默认替代目标
- [ ] 最小确定性防打扰规则：勿扰、通道开关、主动次数限制；此时即约束 MCP 与任务通知
- [ ] 完成/需输入通知、受限会话跳转；来源绑定，不能由普通 MCP 状态意图伪造真实任务完成
- [ ] dsh 接入 spike：版本、事件、新建受控会话、原生审批可达性、完整 TaskSnapshot、输入/取消；pi 作为第二目标可作轻量对照，后续会话接管/审批桥不设为首版门槛

Windows 阶段出口：

- [ ] 安装包无须用户另装 Node；两个 Shell/启动入口不会创建两份 Runtime 或数据库写入者
- [ ] 不打开桌宠窗口也能从已安装启动器启动 Runtime，并从受信管理入口完成首次配对/查看状态/退出；版本不匹配与缺安装明确提示
- [ ] 关闭客户端/宿主后仍跟踪已授权任务；显式退出保存状态、关闭本机服务，提示外部任务可能继续，不伪报取消；开机启动默认关闭
- [ ] 缺 token、错 scope、不允许的 Host/Origin、票据重放均拒绝；撤销客户端后不可继续操作
- [ ] 真实任务状态联动；正常负载下事件到动画 p95 < 300ms，通知调用 p95 < 1s；记录采样与设备
- [ ] 两个会话事件不串扰；重复终态只通知一次；迟到 progress 不覆盖 completed；断线后快照与增量衔接不漏终态
- [ ] 勿扰期间 Maneki 不主动弹出/播报；外部 urgency 不能绕过；用户主动面板仍可用，无语音/模型配置时表达与通知仍可用
- [ ] 统计 Shell/WebView/Runtime/桥/存储的空闲总内存 < 150MB；若未达标记录原因与后续决策，不缩减统计范围
- [ ] Runtime 异常/数据库迁移失败可诊断，未把失联任务标成成功；macOS/Linux 的打包/后台生命周期/通知在平台矩阵另验并保留证据

## M2b — dsh 文字任务闭环与插件首版

依赖：M2 的 Windows 出口与 dsh 原生审批/完整恢复验证。目标：交付第一版“可换装桌宠替我派任务并带回结果”，包含可连接/受控启动共享 Runtime 的 dsh 插件，不等待语音与记事。

- [ ] 明确项目的新会话文字派发入口，默认 ask，展示目标、任务与 harness 数据边界；已有会话仅观察
- [ ] Core Task Broker：clientRequestId 映射全局 brokerRequestId、持久化状态、同项目串行与有界并发、任务列表
- [ ] 真实 Adapter 提交、查询/对账、补充输入及可用的取消；未支持能力明确禁用
- [ ] 原生审批可实际到达，拒绝与无人响应不自动放行；宠物保留整任务授权，宠物审批桥后续扩展
- [ ] 结果摘要、校验后产物引用、完成通知与会话路由
- [ ] 最小 dsh overlay 插件：安装/配对/受控启动/断线/卸载；发布对应版本与能力说明，不因缺语音/提醒而禁用文字任务

Windows 首版发布出口：

- [ ] 关闭语音与模型，从桌宠或 dsh 插件在测试项目新建会话派发 README 翻译任务，完成通知后打开真实产物
- [ ] 同一客户端重发相同 ID 不重复执行；不同客户端使用同一个 clientRequestId 不混单，下游使用不同 brokerRequestId；同入口键换内容拒绝
- [ ] 实际危险操作在临时测试目录中被执行侧阻塞；拒绝/超时后文件未变，审批参数变更须重新批准
- [ ] 原生权限提示只能打开 harness 审批入口，不经普通任务回复/语音回答代批；可回答的 task.needs_input 与审批事件区分
- [ ] Agent 输出里的删除指令仅被展示，不引发 Maneki 新任务；结构化调用缺授权同样拒绝
- [ ] 无审批保障的适配器禁止派发；不启用 skip-permission/全局自动批准选项
- [ ] Runtime 离线期间任务完成/需输入，恢复后能取回完整结果/产物或原问题；status_only 与 unknown 明确降级，不假称完整交付
- [ ] 注入查询快照期间任务完成/输入已被回答，源订阅已就绪且按源位置或经验证的一致性机制合并，不漏终态、不重开旧问题
- [ ] 提交后断线、回执丢失或 Runtime 重启，先对账；not_found/unknown 不触发盲重发
- [ ] 取消未收到确认时不伪报已取消；需要输入时响应绑定原任务/inputId，不能发往另一会话
- [ ] 不打开独立桌宠 App 也能从插件启动/连接已安装 Runtime 并派任务；插件重载/卸载不丢共享记录、不停止其他客户端任务

如果 dsh 无法满足新会话、原生审批或完整恢复要求，保持此阶段未完成，记录实际版本/调用证据，明确提出能力或目标调整；不偷偷换宿主、不以审批桥占位通过。M3/M4 的非执行能力可继续建设。

## M3 — 可选对话与可插拔语音

依赖：M2；任务语音入口集成 M2b。目标：文字与语音走同一流程，语音和模型可分别关闭/替换。

- [ ] `ChatProvider / SpeechRecognizer / SpeechSynthesizer` 独立端口，统一超时/取消/错误语义
- [ ] 首个对话 Provider；whisper.cpp 本地 ASR；首个本地 TTS 引擎经许可、资源与打断验证后确定
- [ ] Provider 配置、模型可用性提示、明确启用/关闭；缺模型不自动下载或转云端
- [ ] “关闭 Maneki 云端能力”与 harness 数据授权分开；交互 Provider 调用显式启用，主动收费调用单独授权与可执行限额，费用不可核查不虚称金额封顶
- [ ] 按键说话、可见采集状态、气泡与可选 TTS，半双工与点击/按键打断
- [ ] 主动语音邀请 + 用户明确回应；可选短时连续对话有超时与一键停止
- [ ] 可选增强单独验收：VAD、唤醒词、回声抑制/全双工，不作为首个可用版本前置条件
- [ ] 多 Shell 音频 owner/有时限租约，勿扰/语音输出关闭/麦克风禁用三个独立状态

验收：

- [ ] ASR/TTS 分别禁用时功能组合正确；全部语音关闭后不占麦克风/不加载语音模型，文字派发仍可用
- [ ] 替换 ASR、TTS 或对话 Provider 各自不改 Core/harness；用真实实现与故障替身验证取消、超时、迟到响应与释放
- [ ] 无对话模型时，结构化文字任务入口、规则提醒、通知与状态联动仍可用
- [ ] 麦克风拒绝/占用、ASR/TTS 失败回到文字；自身播报不会被当用户命令，语音不批准危险操作
- [ ] 关闭 Maneki 云端能力立即阻止自身新云请求并取消在途调用，迟到响应丢弃、不回退其他云端；外部 harness 的独立授权和数据提示准确
- [ ] 未开启主动收费调用时不产生此类调用；额度耗尽/计量失效停止后续调用，Provider 凭证不等于购买/支付授权
- [ ] 两个 Shell 同时连接时一次交互只采集/播报一次，owner 失联到期自行停用，不在未释放前抢发第二租约
- [ ] 勿扰时用户主动按键可以交互；语音输出关闭不播声；麦克风禁用时任何入口都不能采集
- [ ] 基准设备/模型/输入上记录冷启动、ASR p95 < 1.5s 与结束采集到开始回答目标 < 5s；未达标说明瓶颈

## M4 — 记忆、可靠提醒与主动交流

依赖：M2；语音场景额外依赖 M3。目标：文字优先打通“帮我记一下”，不把语音/LLM 设为必需。

- [ ] SQLite memories/reminders/conversations 与版本迁移；用户查看、删除、保留期限
- [ ] 单次提醒时间解析：规则优先，LLM 可选，UTC/原时区保存，歧义先确认
- [ ] 事务写入提醒与待投递项、最近到期唤醒、启动/休眠/时钟变动后补扫
- [ ] 多通道送达与按 reminder/occurrence/channel 去重，区分系统受理/用户确认/失败
- [ ] `maneki_remind` 独立 scope 与用户授权、来源配额；跨来源越权拒绝
- [ ] 主动性引擎扩展触发器/预算；默认勿扰不穿透，恢复后合并补发，重提显式开启且有上限

验收：

- [ ] 关闭语音与对话模型，通过文字创建/查询/删除提醒；启用语音后复用同一业务流程
- [ ] 创建“半小时后提醒看构建结果”，重启、休眠恢复与时钟变化后按规则补发；两个 Shell 不重复调度
- [ ] 默认勿扰时段 Maneki 零主动打扰，包括高优先级；恢复后显示原到期时间与待查看事项；语音输出关闭不阻塞文字通知
- [ ] 注入“发出后记账前崩溃”，记录允许重投边界，Shell 合并重复 ID；不宣称外部通知严格一次
- [ ] OS 拒绝通知显示投递失败，不能标为用户已看见；提醒创建未落库不返回成功
- [ ] 用户数据删除与日志脱敏可核查；关闭 Maneki 云端能力后自身不发送记忆/录音；已运行非勿扰时提醒到通知调用 p95 < 1s

## M5 — 第二 harness 与完整助理体验

基础依赖：M2b。目标：增加经验证的第二宿主和库模式，按 M3/M4 完成情况追加语音与提醒体验；不让可选能力阻塞文字插件交付。

- [ ] 统一文字/语音意图分流；任务列表、多会话关注、补充输入、审批回到受信 UI
- [ ] 在 M2b 已发布的 dsh 插件上复测共享状态、重载与生命周期，不把最小插件推迟到本阶段
- [ ] dsh/pi 等 Adapter 按 M2 spike 的真实能力完善；generic-cli 只提供安全配置范式，不承诺任意 CLI 可派发
- [ ] npm Core 嵌入最小示例，验证不依赖 Shell/Node IO/语音/harness SDK
- [ ] 公开已验收宿主版本、平台、能力矩阵与接入文档
- [ ] 可选增强按需另验：已有任意会话接管、宠物审批桥；bridge 需操作级查询/持久化单次认领/断线对账，不满足就不开放

验收：

- [ ] 第二 harness 的文字任务/原生审批/完整恢复通过；语音任务验收另依赖 M3，提醒集成另依赖 M4，不阻塞前者
- [ ] 桌面与 overlay 同时连接时共享任务；若已启用 M4 提醒则同样共享。某个 Shell 断开不丢状态、不重复执行，Runtime 失联时显示降级
- [ ] 至少两个不同 harness 的真实接入验证统一契约；分别列出观察与执行能力，缺少的能力不伪装
- [ ] 第三方只嵌入 Core 并注入替身端口即可运行状态/提醒规则示例；无监听端口、模型下载和隐式文件 IO
- [ ] 复测总资源与安全恢复场景；macOS/Linux 各自验收前不宣称正式支持
- [ ] 若开放 bridge：模拟批准被消费后回执丢失，仅查询状态、同 operationId 不再执行；外部结果 unknown 时不能换审批 ID 重试

## M6 — 受控扩展与生态

持续建设；不能用“权限清单”代替安全沙箱。

- [ ] 第三方技能代码隔离方案、broker 权限、资源/目录/网络限制与撤销机制
- [ ] 安装/更新来源验证；若引入签名，明确公钥信任、轮换、撤销与防降级
- [ ] 在 v1 基础上扩展动作包制作/导入工具、素材管线脚本与授权文档，不推迟 M1 的基本格式
- [ ] 社区分发约定、兼容迁移、多宠与文档站，按实际需求逐项推进

开放验收：

- [ ] 恶意技能读未授权目录、联网、执行命令及耗尽资源被实际隔离；普通子进程/Worker/VM 不作为通过证据
- [ ] 更新新增权限需要重新授权；撤销/卸载终止调用并清理凭证，坏包不替换正常版本
- [ ] 若隔离不可行，保留受信内置技能与数据动作包，第三方可执行安装入口保持关闭
