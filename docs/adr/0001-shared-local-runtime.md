# 插件与桌面界面共享一个本地助理 Runtime

状态：已接受（2026-10-30，grill-with-docs 第一轮 Q2；第二轮 Q9 明确生命周期）。

Maneki 安装一次共享本地 Runtime，各 harness 插件和桌宠界面作为客户端；使用插件不要求先打开独立桌宠 App。选择此方式是为了共享记忆、提醒、任务状态和音频协调，避免在每个宿主中重复维护一套完整助理，也避免把桌面窗口是否打开误当作助理是否可用。

代价是安装与生命周期需要明确管理：插件只能连接或受控启动已安装的可信 Runtime，并展示未安装、不可用与版本不匹配状态。关闭窗口/插件不停止后台跟踪，明确“退出助理”才停止本机服务，开机启动默认关闭；外部任务是否取消另行确认，不能在退出时假称已取消。

决定不采用每个 harness 插件各自维护完整助理的方式，也不把 Runtime 生命周期绑定到桌宠窗口或某个宿主的父进程。这样增加独立启动/管理的验证成本，但共享任务/记忆与多个界面下的行为一致性更清楚。实现规范见 [architecture.md](../architecture.md)，本 ADR 不宣称打包与后台生命周期已验证。
