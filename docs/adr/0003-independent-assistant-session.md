# Maneki 独立拥有主会话，以分能力契约连接执行宿主

状态：已接受（2026-11-01，grill-with-docs Q1/Q2/Q4/Q5/Q6）。

Maneki 拥有自己的助理身份、个人上下文和常驻主会话，桌宠与 harness 插件是共享视图；dsh/pi 承担具体工程任务。选择独立主会话，避免助理生命周期、个人记忆和跨宿主行为被某一个 harness 的会话语义绑定；代价是必须自行实现最小对话编排、历史持久化与任务回传，不能把已有接口类型称为完整助理。

首版继续先验证 dsh 新建受控任务与原生审批，pi 随后。已有会话介入按真实宿主能力追加，默认排队或用户选择的指导，明确要求才打断；读取会话历史不代表控制运行中会话。各类能力分别以明确契约注册、替换和禁用，取代“所有内置能力实现同一插件接口”的要求，避免把设备、形象包与执行宿主塞进同一生命周期。第三方可执行代码仍须通过隔离验收。

不采用某个 dsh/pi 会话充当助理大脑的路线；它可缩短原型开发，却使宿主故障、版本与权限设置直接影响助理身份和所有视图。保留共享 Runtime 与纯 Core 的既有边界，不引入通用插件内核或另一个代码执行 harness。实现规范以 [architecture.md](../architecture.md) 为准；本决策不表示主会话或会话控制已经验收。
