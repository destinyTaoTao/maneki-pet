# 模板轻陪伴先行，陪伴表达与事项投递分离

状态：已接受（2026-11-14，用户确认推荐方案；本轮仅设计文档）。延续 ADR-0005 的独立助理、共享 Runtime 和 Provider 授权边界，不取代 #66 语音与 #67 显式记忆的验收。

小招的陪伴价值包括符合角色身份的日常台词，不必每句都有任务信息。首批以确定性规则、原创模板、文字气泡和既有短动作交付；模型润色、主动朗读、会话动态提示与长期偏好分别后续接入。选择它是为了在没有模型、语音或宿主的条件下先验证陪伴体验，承担的代价是首批语言变化和自定义人设表达有限。固定周期直接调用模型会增加主动消费与不确定性；要求每句都有任务事实又会把陪伴收缩为状态播报，均不采用。

自动碎碎念是可错过的轻量表达，用户设定的提醒是需保留投递状态的安排；两者分开预算与恢复。前者可以保守占用预算后丢弃，不能通过重试追求送达而制造重复打扰；后者保持独立可靠调度。自动台词不自行进入主会话历史、摘要或长期记忆，用户明确回应后才作为引用数据进入本轮对话。这项边界避免把角色生成的自言自语积累成用户事实，也避免改变已有提醒承诺。

规范见 [architecture §4.3.1](../architecture.md#light-companionship)，具体 Schema 与兼容策略见 [§4.3.2](../architecture.md#companion-protocol-v1)，实施顺序和验收见 [roadmap](../roadmap.md#light-companionship)。协议细化保持同一 SQLite 连接，偏好独立保存并投影到设置，防止旧版保存设置时丢失；功能降级保留当前业务数据，不用整库恢复回退提醒状态。本 ADR 不另定义接口、数值或实现状态。
