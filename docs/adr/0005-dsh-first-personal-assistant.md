# 独立个人助理先行，近期只通过 dsh 集成

状态：已接受（2026-11-07，grill-with-docs Q1–Q11）。延续 ADR-0001 的共享 Runtime 与 ADR-0003 的独立主会话，取代 ADR-0003 中“先完成 dsh 工程派发、pi 随后”的近期优先级；工程执行的授权、原生审批与完整恢复要求保持有效。

近期只适配 dsh，先补插件连接、配对、受控唤起和助理退出流程，再交付文字对话、个人待办与单次可靠提醒，接入按键语音后才单独开放通过验收的 dsh 工程派发。dsh 插件承担主要使用和配置入口，Runtime 拥有主会话、全局设置、持久化与调度；关闭 dsh 或窗口不停止提醒，选定模型服务可用时仍可通过桌宠聊天，明确退出助理才停止后台。

选择这一边界是为了让日常对话与提醒不依赖宿主存活，也不被工程审批/恢复缺口阻塞。代价是助手必须独立配置模型并实现历史、调度、生命周期和资源管理；不采用把某个 dsh 会话作为助理大脑或把全部状态放进插件宿主的方式。不同 dsh profile 默认共享一个个人助手；配置在 dsh 内编辑，由 Runtime 统一保存，避免与桌宠设置互相覆盖。

个人待办、提醒与助理任务分别建模，常规对话不直接操作项目文件或运行命令。交互、历史清除、语音与配置的规范及验收分别见 [architecture.md](../architecture.md) §4/§6 与 [roadmap.md](../roadmap.md)；本 ADR 只记录取舍，不宣称能力已实现。

参考 [dsh-pet](https://github.com/PC2005-cloud/dsh-pet) 的一体化聊天、语音与待办体验，以及 [SuperAgent 的注意力原则](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/main/docs/000-philosophy.md)：持续跟踪，在需要决策、阻塞或有结果时通知。采用这些体验与协作原则，不引入团队消息接入或通用多 Agent 编排平台。
