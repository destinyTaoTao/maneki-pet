# 工作日提醒的接入与验收

以 `87b7976` 为基线，验收「每个工作日上午九点提醒我休息」。规则使用现有的 `reminder_recurring` 身份。工作日期按用户时区中的周一至周五判断。规则保存本地日期，加载时按时区规则计算到期时刻，认领在通知前持久化。[README](../../README.md#weekday-reminders) · [契约](../architecture.md#weekday-reminders)

## 回执与兼容

- SDK、CLI 和 MCP 用同一凭证并发创建、取消时返回各自的首次回执。周五九点之后创建，工作日列表显示下周一九点，每日规则仍显示周六九点。同一请求 ID 更换周期返回 409。
- 已取消的规则重放原创建请求只取回执。撤销后管理员仍能按登记名称和准确系列 ID 取消。既有每日 API、旧每日桥及改期范围保留。工作日使用独立的 SQLite KV，旧 Runtime 只调度自己识别的每日目录。[跨入口回归](../../packages/cli/tests/weekday-reminders-integration.test.ts)
- Runtime 回归验证 UTC 周四、本地已是周五时照常投递，UTC 周五、本地已是周六时不补发。工作日规则在真实时区的 DST 缺失与重复分钟均跳过。还覆盖跨周末恢复、通知仍在途时重开库、同身份共用额度及每日与工作日存储故障隔离。[调度回归](../../packages/runtime/tests/daily-reminders.test.ts)

## 真实 dsh 调度

Windows x64、Node 24.12.0、dsh 0.2.2-rc.1。隔离 profile 用本地确定性 Provider 驱动 dsh 原生对话循环，经实际 stdio MCP 创建和取消九点规则。测试推进上海时区的本地日期，用同一授权下的每日提醒作阳性对照。

| 本地时间 | 工作日规则 |
| --- | --- |
| 11 月 20 日周五 09:00 | 调用通知器一次。 |
| 周五同日重启后 | 零重投，每日对照正常投递。 |
| 11 月 21 日周六、22 日周日 | 两天均零投递，每日对照各一次，查询显示下一次为周一 09:00。 |
| 11 月 23 日周一 09:00 | 投递一次。dsh 随后查询并按准确系列 ID 取消，取消重试返回原回执，创建重试没有恢复规则。 |
| 11 月 24 日周二 | 零投递，每日对照正常投递。 |

验收使用模拟时钟与注入通知器。在线模型自主选择工具、真实系统通知横幅及其他平台仍待单独验证。[dsh 接入](../../apps/dsh-plugin/README.md#让-dsh-安排工作日提醒) · [可复跑脚本](../../scripts/acceptance-dsh-reminder-weekdays.mjs)

全仓构建、类型检查和按包串行测试通过，739 项通过，3 项按条件跳过。既有每日创建、取消、改期通过真实 dsh 回归。插件打包检查确认包含独立工作日 patch。
