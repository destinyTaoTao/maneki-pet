# 每日提醒的 dsh 接入与重启验收

以 `b135d18` 为基线。本轮验证「每天上午九点提醒我休息」。每日规则有单独的 `reminder_recurring` 权限，只能创建、读取和取消本身份的规则。既有单次提醒调度共用通知预算。每日规则使用现有 SQLite 内容存储，无数据库迁移。[README](../../README.md#daily-reminders) · [调度与授权契约](../architecture.md#daily-reminders)

## 真实 dsh

Windows x64、Node 24.12.0、真实 dsh 0.2.2-rc.1。隔离宿主使用本地确定性测试 Provider，从原生对话经 stdio MCP 创建和查询九点规则。Runtime 采用用户设置的 `Asia/Shanghai` 时区。测试预置了同名十点对照。

| 本地时间 | 结果 |
|---|---|
| 11 月 21 日 09:00 | 九点规则调用通知器一次。 |
| 11 月 21 日 10:00 | 重启 Runtime 后只有十点对照调用通知器，九点没有重投。 |
| 11 月 22 日 09:00 | 九点规则调用通知器一次。第二轮 dsh 查询后用系列 ID 取消；取消和创建请求都可重取原回执，取消的规则不复活。 |
| 11 月 23 日 10:00 | 重启后只有十点对照投递。已撤销的 dsh 凭证无法继续查询。 |

本轮推进隔离进程的时钟，并使用注入通知器观察实际调度调用。线上模型自主选工具、Windows 通知横幅及其他平台仍待验。既有 dsh 单次取消和改期通过真实宿主回归。[复验脚本](../../scripts/acceptance-dsh-reminder-recurring.mjs) · [dsh 配置](../../apps/dsh-plugin/README.md#让-dsh-安排每日提醒)

## 幂等和失效处理

- SDK、CLI、MCP 并发创建时，使用同一请求 ID 只保存一条规则。并发取消返回原回执。单次凭证不能访问每日接口，混签被拒绝。撤销后仍可由本机管理员按登记名称和系列 ID 停止规则。[跨入口回归](../../packages/cli/tests/daily-reminders-integration.test.ts)
- Runtime 在通知调用前事务提交认领并推进日期。在 Windows 隔离子进程中注入通知器，收到调用后保持结果未返回，强制结束进程。重开同一 SQLite 后，当天调用零次，次日一次，系列 ID 保持一致。认领和受理之间中断时，当次可能错过。
- 规则持久保存下一本地日期，加载时按当前时区库计算 UTC。复核发现同时持久保存并校验两个值会在时区规则升级后误判损坏。本轮将本地日期作为持久调度依据，首次回执仍按原值重放。Runtime 回归也覆盖夏令时缺失和歧义、同日迟投、跨日跳过、回拨、通知预算及每日存储错误隔离。[调度测试](../../packages/runtime/tests/daily-reminders.test.ts)

全仓构建、类型检查和按包串行测试通过。710 项通过，3 项按条件跳过。插件打包清单包含独立每日提醒 patch。
