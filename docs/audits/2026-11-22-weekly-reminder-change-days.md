# 更换指定星期提醒的验收

以 `e104202` 为基线，验收「把每周一、三、五上午十点的休息提醒改成每周二、四上午十点」。沿用 `reminder_recurring_reschedule` 和同名创建身份。目标通过系列 ID 和版本选定。改期原子提交星期集合、下一次日期、认领日期下界、版本、额度和回执。[README](../../README.md#weekly-reminder-change-days) · [契约](../architecture.md#weekly-reminder-change-days)

## 真实 dsh

Windows x64、Node 24.12.0、dsh 0.2.2-rc.1。用隔离 profile、本地确定性 Provider 和真实 stdio MCP 对话查询和改期。存在正文和时刻相同的周二、四对照系列，dsh 从原星期集合识别实际目标。调度测试等待扫描完成，并使用同一时刻的每日对照。

| 上海当地十点 | 目标系列通知器调用数 |
| --- | ---: |
| 11 月 23 日周一、25 日周三、27 日周五 | 各 0 次 |
| 11 月 24 日周二、26 日周四 | 各 1 次 |
| 周二、周四在同一时刻重启 | 各 0 次 |

第二组在 11 月 30 日周一 10:00 认领后把时钟回拨到 09:30，改为每周一、二、四。两次重启到周一 10:00 均为零次。下次从旧周三提前到 12 月 1 日周二 10:00，当次为 1，重启为 0。两组均保留原系列 ID、时区和本地时刻，版本从 1 升为 2。换序重试与重启后的重放返回首次回执，换集合复用 ID 或提交旧版本返回 409。

验收使用模拟时钟和注入通知器。在线模型自主选择工具、系统通知横幅和 macOS/Linux 实机体验待单独验证。[dsh 接入](../../apps/dsh-plugin/README.md#在-dsh-更换指定星期) · [复验脚本](../../scripts/acceptance-dsh-reminder-weekly-change-days.mjs)

## 契约回归

- HTTP、SDK、CLI、MCP 并发提交同一请求，包括乱序星期数组，均取得同一版本 2 回执。验证创建凭证无改期权、其他重复周期拒绝星期字段、额外字段及非法集合被拒绝，以及同名同时间的其他系列保持版本 1。[跨入口测试](../../packages/cli/tests/weekly-reminder-change-days-integration.test.ts)
- Runtime 回归覆盖旧规则兼容、跨日推进、连续改期、重启与时钟回拨、认领边界事务回滚、损坏的日期下界拒绝认领和改期但允许取消。旧的只改时刻入口继续沿用原请求和回执。[调度回归](../../packages/runtime/tests/daily-reminders.test.ts)

全仓构建、类型检查和按包串行测试通过，781 项通过，3 项按环境条件跳过。既有指定星期创建与取消、指定星期只改时刻、工作日改期三个真实 dsh 脚本也通过。
