# 每日提醒改期验收

基线为 `d88e1f0`。本轮验收「把每天上午九点的休息提醒改到每天上午十点」。每日改期单独签发 `reminder_recurring_reschedule`，只列出及更新同名创建身份的活跃规则。旧列表和规则存储形状继续兼容，已有规则的初始版本为 1。[接入指南](../../README.md#daily-reminder-reschedule) · [协议](../architecture.md#daily-reminder-reschedule)

## 状态与请求回执

- 系列 ID、正文和时区保持一致。版本与新本地时刻在同一事务更新，并持久保存首次回执。调度不回退到已有的日期之前。旧时刻替换后，下一次调度使用新时间。
- 同一请求经 SDK、CLI 与 MCP 并发执行，只更新一次。重试原参数返回原回执。已提交请求换目标或时间、不同请求提交旧版本均返回 409。其他身份的系列返回 404。[跨入口回归](../../packages/cli/tests/daily-reminder-reschedule-integration.test.ts)
- 旧版本 Runtime 使用的每日规则形状保留，版本单独存储。版本数据损坏时拒绝新的改期，已提交的原回执仍可取回，原有每日查询与调度继续服务。Runtime 回归覆盖版本、配额和回执写入失败时的事务回滚，以及通知仍在途和时钟回拨时的日期下界。[调度和版本测试](../../packages/runtime/tests/daily-reminders.test.ts)

## 真实 dsh 与两个到期场景

Windows x64、Node 24.12.0、dsh 0.2.2-rc.1。分别创建两个隔离 profile 和 SQLite 数据目录，用本地确定性 Provider 驱动 dsh 原生对话循环，使用上海时区、真实 MCP 桥和注入通知器。

| 改期时的状态 | 原时刻与新时刻的观测 |
|---|---|
| 当天九点还未认领 | 11 月 21 日九点只有对照项投递，目标零次。重启后当天十点目标投递一次。 |
| 当天九点已投递 | 11 月 21 日九点目标已投递一次。改期并重启后，当天十点只有对照项，目标零次。11 月 22 日十点目标投递一次。 |

两组都保留原系列 ID 并从版本 1 升到 2。dsh 在 MCP 中重放原参数返回初次改期回执，旧版本及已成功请求换参数返回冲突。重启后通过 SDK 重试也取回原回执。本轮验证调度器对通知器的调用，在线模型自主选工具、系统通知横幅和其他平台仍待验证。[dsh 接入](../../apps/dsh-plugin/README.md#让-dsh-改期自己安排的每日提醒) · [复验脚本](../../scripts/acceptance-dsh-reminder-recurring-reschedule.mjs)

全仓构建、类型检查和按包串行测试通过，725 项通过，3 项按条件跳过。原 dsh 每日创建与取消验收通过，打包检查确认提供新的独立 patch。
