# 宠物窗口与底部交互设计澄清

状态：2026-11-04 用户以“按你的推荐来”确认下述四项方案。按 grill-with-docs 完成澄清；实现规范同步至 architecture.md，本记录保留需求来源与验证边界。

## 用户已提出的目标

- 去掉截图中包围人物的透明矩形框。
- 操作围绕宠物自身，控件放在人物正下方，参考 Codex 宠物的紧凑布局。
- 底部三个入口按文字输入、语音、下拉设置的顺序组织，并美化控件。

## 代码事实与证据边界

- `apps/desktop/src-tauri/tauri.conf.json` 已启用透明窗口并关闭装饰，但没有显式关闭原生窗口 shadow。锁定依赖的默认 shadow 行为是矩形边框的强候选原因；仍需真机开关验证，不能仅凭截图定因。
- `apps/desktop/src/style.css` 没有整窗边框，宠物按钮是 224×224 的矩形。素材透明不等于该矩形区域对下层窗口放行鼠标。
- `apps/desktop/src-tauri/src/lib.rs` 的托盘穿透开关作用于整扇窗口，不能直接满足“透明部分穿透，人物与控件可操作”。
- 当前点击人物播放 wave，拖动从整个宠物按钮发起；点击与拖动的边界需要与新交互一致。
- 桌面没有主会话聊天、录音或 ASR 实现。新增输入框和麦克风外观不代表这些功能已经可用。主会话与 dsh 工程任务的边界继续遵守 ADR-0003。
- 本轮只读核查发现运行中的本机安装程序与仓库 release 程序哈希一致；没有据此宣称所有源码或窗口行为已真机验收。

## 已确认的方案

1. 人物轮廓与显示中的控件接收操作，其余透明区域点击交给下层窗口；拖动只从人物发起，沿用点击 wave 与拖拽/甩抛。
2. 悬停人物或键盘聚焦时显示人物正下方的控制条；输入与设置展开时保持显示，离开后延迟淡出。
3. 第一项为可编辑的紧凑文本框，后接麦克风与下拉设置按钮；奶白胶囊、暖橙强调、统一细线图标，移除旧的独立设置按钮。
4. 本轮仅实现窗口交互与控件布局。文字仅为当前窗口内草稿，不提交；语音入口明确未启用且不采集。保留现有设置内容，不新增对话 Provider、ASR 或反向派发。

“宠物交互区”与“宠物控制条”已在 GLOSSARY.md 定义。未新增难以逆转的选型，本轮不新建 ADR。Windows 需实测窗口阴影、透明处穿透、轮廓命中、拖动、控制条与菜单、已有 dsh 状态联动，并更新正确的本机安装路径；macOS/Linux 另行验收。
