# 外部 agent 精确改期提醒

本轮以 `2590d83` 为基线，验收「把刚才那个休息提醒改到一小时后」。改期凭证与创建、查询和取消各自签发。改期只作用于同名创建身份下尚未认领的提醒。调用方提交查询得到的版本、完整提醒 ID 和独立请求 ID。[接入指南](../../README.md#agent-reminder-reschedule) · [协议](../architecture.md#agent-reminder-reschedule)

## 事务和重试

- 改期仅更新原行的到期时间并增加版本。SQLite 同一事务保存更改与首次回执。再次收到相同参数时返回第一次计算出的到期时间，跨进程和 Runtime 重启也一致。
- 其他身份或不存在的提醒返回相同的 404。旧版本、已认领，以及已成功的请求 ID 被用于不同版本、目标或延时，均返回 409。改期与取消、投递竞态按事务先后决定。
- 只有成功的新改期消耗该身份的小时额度。独立审查复现了跨小时后回拨可借用新小时剩余额度的问题。修复后，先用满旧小时，再由新小时回拨时，新请求返回 429，已提交的回执仍可重取。撤销按已登记名称办理，查询和已有调度独立生效。[Runtime 回归](../../packages/runtime/tests/agent-reminders.test.ts) · [跨入口测试](../../packages/cli/tests/reminder-reschedule-integration.test.ts)

## dsh 到期验证

在 Windows x64、Node 24.12.0 和 dsh 0.2.2-rc.1 的隔离 profile 下，用本地确定性测试 Provider 驱动真实 dsh 对话循环。第一轮输入「半小时后提醒我休息」。第二轮用上一轮创建回执和当前列表选中「刚才那个」，从两条同名「休息」提醒中改期正确的一条。回执保留目标 ID，版本从 1 变为 2。旧版本、同一请求 ID 改目标或延时均返回冲突，原参数重试返回原回执。

| 检查点 | 调度结果 |
| --- | --- |
| 目标的原到期时刻 | dsh 退出并重启 Runtime，推进隔离时钟。仅同名对照项触发一次，目标保持待投递、尝试次数为零。 |
| 目标的新到期时刻 | 从同一 SQLite 恢复并推进时钟，目标触发一次。ID 及正文保持一致，到期时间为首次改期受理后 3600 秒。 |
