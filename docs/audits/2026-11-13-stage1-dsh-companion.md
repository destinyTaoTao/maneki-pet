## 回执延迟的根因与修复

冷启动时，原生管理进程在约 373 ms 输出成功、378 ms 退出，stdout 的 close 事件却直到本次诊断停止后台后才发生（约 101872 ms）。后台已有实例时，对照调用在约 240 ms 完成。继承管道的后代进程延长了 EOF 等待；插件原先使用 `execFile` 完成回调，导致其管理操作长时间占用。

插件增加内部 `runControlProcess`，在原生进程退出且完整回执到达后返回，释放当前读管道。保留 120 秒期限、取消、16 KiB 上限及固定诊断；JSON 与凭证校验仍由既有管理代码处理。新测试用真实子进程创建持有 stdout 的后台后代，先复现超时，再验证修复；另外覆盖输出超限、取消和无换行回执。

本轮候选插件在独立目录打包并安装到测试 dsh。测试后台停止后，由真实项目 B 命令处理器重新打开助手，含快照核对的调用耗时 435 ms，消息 seq 15–18、提醒 ID 与投递次数均保留。插件候选仍使用 0.3.0 版本，仅在验收目录中重打包；已有封存发行包继续对应原交付记录。

## 2026-11-22 · 主会话双凭证回归（#56）

使用隔离 Windows Runtime、两个独立的 `assistant` 凭证和一个仅可观察的 dsh 凭证。通过正式 HTTP 提交、轮询与恢复历史，确认同一主会话只接受一个进行中的请求。原客户端重试可取得原回执，第二客户端无法轮询该请求。使用同一 SQLite 重启后，第二客户端读到相同历史，并可使用自己的同名请求 ID 继续对话。项目观察仍可查询，普通模型输入只带入前序主会话内容。

全仓按包串行测试 786 项通过、3 项按环境条件跳过，包含三种本地词表的跨进程联验。本回归使用本机 Provider 替身和合成宿主观察，真实桌面及 dsh 的验收以本记录前文为准。工程任务摘要回传仍依赖独立的派发和恢复验收。[回归测试](../../packages/runtime/tests/assistant.test.ts)
