# 对话管理待办与提醒（2026-11-09）

关联 [#63](https://github.com/destinyTaoTao/maneki-pet/issues/63)，基线 `main@f4d4a15`，设计先行 `ab5a3f9`。本轮补齐近期 dsh 个人助理的确定性对话管理，其他宿主、MCP 提醒工具、每日简报及工程派发仍后置。原生授权、真实音频设备和云端账号等人工项继续保留。

## 实现与使用

- 通过现有 chat 路径查询全部/完成状态/今天/逾期待办，查询全部/今天/待投递提醒；修改待办标题、备注、截止日期或清除日期；按完整名称改期/取消 pending 提醒。时间与截止日期分开，不自动把改名解释成设截止日期。查询最多 20 项、长名称截断展示，同名候选最多 8 项；名称/备注换行作为数据转义，不伪造候选行。
- Core 解析当前用户的完整命令与明确时间；Runtime 的 PersonalDialogue 负责候选选择、临时澄清与办理，复用原 mutations 的稳定 ID、对象版本、客户端请求幂等与 SQLite 事务。普通模型回复、历史摘录及 dsh 输出不进入规则执行，express 不能调用个人接口。
- 同名先列候选，回复“第 N 个”只操作提示时绑定的对象版本；目标更新/删除后要求重述。缺时间可以先说“提醒我开会”，再补“明天下午三点”。相对时间从补充回复时刻计算，不猜测上午/下午、无效日期或 DST 重复/缺失时间。
- 澄清每客户端一项、全局至多 32 项、5 分钟有效，绑定会话 epoch 和时区；重启、清空历史、设置变化、撤销或新命令/无关聊天使其失效。状态仅在内存中，历史里还看得到提示不代表授权仍有效。取消只放弃未提交澄清，不假报撤销已办理事项；无上下文的独立时间/序号明确提示重述，不付费猜测意图。
- 对话取消 pending 提醒复用 reminder.delete，删除未投递记录；sending / accepted / failed / cancelled 不通过对话假报撤回或隐式重试。完成/删除待办维持既有关联提醒处理，在途不承诺撤回。批量清空继续使用面板范围预览及再次确认。
