# #65 · 逐会话进度、来源与无模型查询

执行跨 2026-11-13 至 11-14（Asia/Shanghai）。基线 `main@eb7fdb8`，契约先行提交 `15ad707`，实现随本记录单独交付。规范见 [architecture §6.9](../architecture.md#session-observations)，票据 [#65](https://github.com/destinyTaoTao/maneki-pet/issues/65)。

## 实现与兼容

- 复用 dsh 的 `session/event` 和既有 Adapter 序号/终态过滤。插件保留至多 64 条逐会话记录，独立向新路由上报；旧表情入口继续工作。
- Runtime 按凭证客户端与插件实例隔离观察，整批校验、拒绝倒退报告与同序号变更。租约 15 秒过期后保留最后事实并标记不可用，心跳不改写会话事件的观测时间。来源至多 64 个，回收失联来源时保留在线来源。
- assistant 快照增加可选 observations，新增受 assistant 权限隔离的变更通知；“会话”页与规则式进度问答共用这些记录。文字查询在对话模型调用前处理，语音后续复用同一入口。
- 定位提供 profile、实例/客户端来源（卡片标题悬停）、项目目录名和完整会话 ID。宿主原生列表可用 ID 对照，原生跳转与历史会话发现仍另验。
- 迁移先更新 Runtime/桌面，再更新插件。新插件连接旧 Runtime 的 404 会明确提示，同时继续上报原表情；旧客户端连接新 Runtime 保持原行为。protocolVersion=1，SQLite 无迁移、生产依赖无新增。封存 alpha.2 发行包仍对应原哈希。

## Windows 真实宿主场景

环境为 Windows x64、Node 24.12.0、真实 dsh 0.2.1-rc.5、源码构建的 Tauri release 窗口。Runtime / APPDATA / DSH_HOME 与两项目目录均位于独立临时验收目录。小招对话模型关闭。

测试宿主使用本地固定流替代模型响应，驱动真实 Agent 循环、宿主自带 `ask_user_question` 工具和会话 API；输入、回答均为测试文本。提问由测试 answerer 挂在宿主的真实 user-questions 服务上，本轮没有通过 dsh Web 输入框人工回答，也未发生真实模型计费调用。

1. 最初两轮自建 Agent 没有挂载提问工具，未形成持续等待，只计作探测。修正测试装配后，A 的真实工具调用进入等待，B 完成；小招记录 A=waiting_input、B=completed，目录名与完整会话 ID 一致。
2. 模型关闭时，通过正式 chat 入口询问“哪个会话在等我”，仅返回 A；“查看会话进度”同时保留 B 已完成。真实原生“会话”页截图观察到两张独立卡片，A 等待、B 已完成。
3. 经宿主 user-questions answerer 返回 A 的测试回答，A 继续并完成。经宿主自己的 prompt/cancel API 向 B 提交并取消测试工作，小招记录 cancelled，未映射为完成；该探测未开放 Maneki 的任务派发或取消能力。
4. 停止已核实 PID 的测试 dsh，保留小招后台。租约失效后，查询回答来源已失联、当前进度不可用。原生卡片保留最后阶段/时间并标明当前未知。
5. 重新启动独立 dsh 实例，收到新实例的新事件后恢复在线来源；旧失联来源仍可辨识。新实例未冒充旧会话历史恢复。宿主原生 list 返回的 A/B 完整 ID、项目目录名与小招一致。

本轮测试会话为 `session-stage65-A`、`session-stage65-B`。真实用户的会话、工程文件和凭证未用作测试输入。

## 事件到动画采样

在源码 release WebView 上，以本地固定回复、每步约 350 ms、轮间约 700 ms 的负载连续执行 12 轮真实 dsh 任务。记录宿主 step/start 与 turn/end 接收时间，并在 WebView 的视频 playing 后使用 requestVideoFrameCallback 记录对应动画首帧。采样期间切回桌宠，使视频实际可见。

24 个目标事件全部匹配对应思考/庆祝首帧，p95=69 ms，最大值=69 ms，满足本场景 < 300 ms 目标。本机时钟用于两侧关联；结果限于本地固定回复、单活跃任务及本机素材，不能代表真实网络模型、长期负载或其他平台。只在本次测试进程设置回环 CDP 诊断端口，配置与代码中没有加入调试端口。

## 回归与审查

新增回归覆盖 A 等待/B 完成、同源跨客户端隔离、重复报告不续租、倒退/同序号冲突、撤销与显式离线、报告/来源容量、正式 HTTP 权限与无模型查询、旧 Runtime 404 兼容、卡片失联文案和数据渲染。

独立审查发现终态淘汰原先按 Map 创建顺序，可能误删最新完成的长任务。交错完成顺序回归先失败，改为按 observedAt 淘汰最早终态后通过。独立复核未发现其他可行动缺陷，复跑插件 13 项与面板 4 项测试通过；随后补充来源满额和 404 兼容测试。

最终 `pnpm -r build`、`pnpm -r test`、`pnpm -r typecheck` 全部通过，384 项测试通过、2 项设备测试默认跳过。分项为 Core 100、Runtime 147、Desktop 84、插件 14、dsh Adapter 22、platform-core 8、B站 5、CLI 4。`pnpm --filter @maneki-pet/desktop tauri build --no-bundle` 的 Windows release 原生构建通过。
