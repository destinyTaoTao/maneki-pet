# Maneki 0.2.0-alpha.2 · Windows x64 个人助理预览

本包提供桌宠、独立个人对话、待办、单次提醒与可选按键语音，近期只接 dsh。工程任务继续在 dsh 原生界面执行；助理反向派发尚未开放。本包为未签名预览，系统来源/SmartScreen 提示由用户判断，不自动绕过。

## 安装和 dsh 接入

1. Windows 10/11 x64；系统需要 WebView2。安装器会按 Tauri 标准流程检查 WebView2，缺失时需要联网获取官方组件，安装/系统安全授权由用户操作。自带 Node 24.12.0，用户无需另装 Node 来运行助理；dsh 本身仍须独立安装。
2. 升级前，在**原先安装版**托盘选“退出助理”，确认后台已停止。只关闭桌宠窗口不会停止后台。运行中安装/卸载会拒绝，不强杀任何程序。旧 MSI 不自动迁移，须先人工处理旧安装。保留数据时不要勾选删除应用数据。
3. 运行同目录 `Maneki_0.2.0-alpha.2_x64-setup.exe`，默认当前用户安装，也可选择含空格或中文的目录。安装后自动登记 dsh 固定入口，不自动配对、开机启动、启用模型或麦克风。先从开始菜单打开 Maneki 可确认桌宠和助手面板。
4. 在已有 dsh **0.2.1-rc.5** 环境执行（把路径换成本包 tgz 的实际绝对路径）：

```powershell
dsh plugin --profile web add 'C:\下载\Maneki\maneki-pet-dsh-plugin-0.3.0.tgz'
```

重启 dsh profile。输入 `/maneki pair`，由用户核对 profile 和“仅状态表达”权限后在原生框确认。不同 profile 须配置不同 profileId；个人助手、待办和配置仍共享。不要把密钥写进项目或 profile 文件。

```text
/maneki status       查看连接状态
/maneki show         唤起同一桌宠
/maneki assistant    打开对话、待办、提醒与设置
/maneki quit         原生确认后退出后台；不取消外部 dsh 工作
```

## 首次可用检查

模型默认关闭也可输入“待办：买牛奶”或“半小时后提醒我休息”。截止日期不会自动设置提醒；完成待办取消尚未投递的关联提醒。系统受理与用户查看分开，“我已查看”不会完成待办，失败项可手动重试但仍受勿扰/限额约束。

对话模型在助手设置中单独配置并启用，本机端点/云端授权分开；密钥不会回显。不复制 dsh 的模型密钥。语音也默认关闭：本地 ASR 需自行安装受信 whisper.cpp，或选择百炼北京 ASR/TTS 并配置独立语音密钥和云端授权，详见 `docs/voice.md`。配置组件检测不产生云端计费调用。

## 用对话管理事项

文字与有效的按键语音转写共用这些规则，不需要启用对话模型：

| 操作 | 示例 |
|---|---|
| 查询待办 | `查看待办`、`查看今天未完成的待办`、`查看逾期待办`、`查看已完成的待办` |
| 修改待办 | `把待办买牛奶改名为买豆浆`、`把待办买豆浆的备注改为无糖` |
| 修改截止日期 | `把待办买豆浆的截止日期改为明天`、`清除待办买豆浆的截止日期` |
| 完成 / 删除 | `把买豆浆标记完成`、`删除待办买豆浆` |
| 查询提醒 | `查看提醒`、`查看今天的提醒`、`查看未完成的提醒`（待投递项） |
| 修改未来提醒 | `把开会的提醒改到明天下午三点` |
| 取消未来提醒 | `取消开会的提醒`（删除尚未投递的记录） |

名称按完整名称精确匹配，可用 `“名称”` 或 `「名称」` 包裹。只改标题不隐式修改截止日期；改名不要混入“明天前”等日期前缀，日期使用独立命令。提醒只接受明确未来时刻，“明天三点”需要补充上午/下午；相对时间从补充回复时刻计算。其他自由表述不保证可办理，模型回答只作为文本。

同名项先列候选，回复 `第2个`；缺时间可以先说 `提醒我开会`，再补 `明天下午三点`。澄清限同一客户端、5 分钟内有效；查询列表中的序号不会自动授权后续操作。回复 `取消` 只放弃待澄清操作。新命令/无关聊天、重启、清空历史、设置变化或凭证撤销后需要重述；目标在其他面板发生变化也会拒绝，避免误改。

已投递或在途提醒不会被对话假报撤回；需要查看失败或已受理记录时使用提醒页。完成/删除待办仍取消尚未投递的关联提醒；截止日期不自动生成提醒。查询最多显示 20 项，同名候选超过 8 项转到面板选择。清空全部待办仍使用面板的范围预览和确认。

## 升级、卸载与回退

0.2.0-alpha.2 增加下述对话规则与澄清，HTTP / 数据 v6 不变；先用旧版退出助理，再同时更新桌面和 Runtime。0.2.0-alpha.1 的封存包保持原样，不能只替换其中的 Runtime 文件。

- 用户数据位于 `%APPDATA%\com.manekipet.desktop\runtime`。更新前先退出后台并备份该目录；备份包含凭证，不要上传或转发。SQLite v5→v6 会在迁移前生成 `runtime.db.bak-5`，其他源版本按原版本编号备份。
- 桌面与 Runtime 随本安装器一起更新，不能只复制其中一个。旧后台版本不匹配时入口会明确拒绝；先使用旧版退出，再打开新版，不能删除锁文件强行启动第二份。
- 卸载前先退出助理。默认保留个人历史、提醒、模型/语音配置与凭证，供重装恢复；卸载只注销属于该安装路径的 dsh 入口。用户选择删除应用数据时才按安装器选项删除，删除/通知身份清理的实际体验仍列为人工验收。
- 禁止直接静默降级。回退时停止后台、卸载新程序并恢复更新前备份，再显式安装兼容版本；恢复旧备份会丢失备份后的修改，旧 Runtime 不接受 SQLite v6。

## 后续源码增量（不在 alpha.2 封存包内）

2026-11-15 的 Runtime 单实例锁需要随构建携带 Windows x64 原生模块；源码组合构建需要 Rust ≥ 1.88 和 MSVC。缺模块或非 Windows 平台会明确拒绝启动，不能删除锁文件绕过；macOS/Linux 原生实现尚未提供。完整或空的新版崩溃残留可恢复，非空损坏元数据仍保守拒绝，详见[原生模块说明](../packages/runtime/native/instance-lock/README.md)。

长期记忆在新构建的助手设置中分别开启写入与召回。先按[EverNook 配置说明](../packages/adapters/evernook/README.md)安装 shim、选择受信 Python/配置/独立配对路径；保存设置后点击“配对 EverNook”，没有隐式配对。写入示例为“记住：我偏好……”，以实际回执为准；结果未知时先到 EverNook 核实，不直接重发。召回需匹配当前消费模型的真实本地 tokenizer；当前支持范围和离线词表校验见配置说明，不支持时聊天继续并提示降级。召回内容会随本轮问题发给你选择的对话模型。清空小招历史不会删除 EverNook 中已保存的副本。

三色 2.0.0 仍为候选：橘色默认、白黑可选，实机观感和资源验收后进入下一预览；批准指纹及现有 alpha.2 保持原样。

## 校验与人工验收

`release.json` 记录源提交、版本与逐文件哈希，`SHA256SUMS.txt` 可与 PowerShell `Get-FileHash -Algorithm SHA256` 对照。哈希证明文件一致性，不证明发布者身份。正式默认形象使用已批准的橘猫娘 1.1.0；包内附代码及第三方许可，未捆绑语音模型。

自动验证与人工项分别记录。仍需人工确认：生产身份的安装界面和既有用户升级、SmartScreen/系统权限、原生配对同意/拒绝及退出、原生输入提交/候选选择/焦点交互、真实麦克风/扬声器、百炼账号/费用/准确率、真实休眠/多屏 DPI 和长期资源。macOS/Linux 未在本机验证。本预览不代表完整 M1/M2/M3/M4 或工程派发出口通过。
